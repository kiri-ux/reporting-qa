AND AN OLDER EXPORT COULD BEAT A NEWER ONE
=============================================
Which is a real bug, and it is exactly the shape of what you are seeing.

Rows are de-duplicated on order id, line item id and flight dates - so the same
line item in two files collapses to one. THE STATUS WAS NOT PART OF THAT KEY.
Two exports pulled a week apart carry the same order, the same line and the
same dates, and not the same status - so an order that was "RFP Pending" on
Tuesday and has been IO Live since kept the Tuesday row, got thrown out by the
RFP filter, and the live row behind it was discarded as a duplicate.

An old file left in the folder quietly beat the one that arrived this morning,
while the page said "Overlapping exports are fine".

Two fixes, because either alone leaves half of it:

  The status is part of the key now, so both rows are read and merged - and the
  merge already knew what to do with them: live wins over not-live, and every
  status the line has carried is kept in its own words.

  Files are read NEWEST FIRST, off the S3 timestamp rather than the filename.
  Where two rows really are identical the fresher file is the one that lands.
