AND THE CODE HAD A REAL FAULT UNDERNEATH IT. The sync treats the S3 folder as
"every CSV under this prefix, merged, newest first". Nothing ever removed the
older days, so every export ever dropped in that folder was downloaded and
merged on every single sync. Two problems, and the second is the bad one:

  * It is gigabytes an hour of downloading and parsing on a box you have been
    telling me is slow. Your load average of 7 has a candidate now.
  * A run from three weeks ago is a picture of the orders as they were three
    weeks ago. The merge keeps whatever line item today's file did not happen
    to carry, so the board could be half today and half a fortnight back, with
    nothing on screen saying which half was which.

It now reads the newest run and anything within twelve hours of it - which
keeps 07:32 and 07:34 together, and keeps the small stephens file from 07:28 -
and skips everything older. A file you name outright is never skipped.

and how many older exports it walked past:

  orders-db-stephens-1_20260901_0728_0.csv (0 MB). 4 older export(s) in that

"3 file(s)" was never enough to tell a complete export from half of one.
