THE ROLL-UP CHANGE - THIS IS THE ONE
====================================
An order line row is one client and one product rolled up across every line
item behind it, and its date window is the widest of them. Everything asked
that window whether the client ran this month, which is the wrong question, and
it is behind most of what you have sent me today.

The per-line detail has been on the row since build 109 and nothing read it for
this. It does now. Three cases, all yours:

TODD'S JEWELRY 47117. Eight line items, every one IO Complete and finished by
31 July, plus one "IO Pending Launch: Element Missing" dated 24 August. Rolled
up, the window spanned August. A line waiting on creative has its flight dates
set already, so on dates alone it reads as delivering - and it was the only
thing holding that row on the board. Pending Launch is not running, whatever
the dates say. The row is gone and reads "no line item was running in August
2026".

ROOF TOP SERVICES 43005. One complete Meta, one cancelled dated to 30 August,
one starting in September. Something is "running" in August only if you count
the cancelled one - and a cancelled line is not a reason to pull a report. Your
words, and now the tool's:

  no line item was running in August 2026, and nothing served for this client
  that month either

It only mentions the serving file when one was actually loaded. Silence from a
file that does not exist is not evidence.

"DO I NEED TO DO ANYTHING DIFFERENTLY SO ORDERS AREN'T MISSED?"
===============================================================
Not to the exports themselves - but you had no way to check, and now you do.

The order export arrives as several files: one per partner for some of them,
and one "all" file covering everybody else. Woof Boom Muncie has no file of its
own, so order 52600 can only come from "all". If a per-partner file stops
arriving, or a partner is in none of the files, their clients simply are not on
the board. No error, no empty table - the cycle is just quietly smaller, which
is the worst way for this to fail.

THE ORDERS PAGE NOW NAMES THEM. The reporting breakout sheet knows every
partner there is; anything on it with not one order line loaded is listed at
the top of that page:

  N partners on the reporting breakout sheet have no orders loaded at all.

Some will be genuinely dormant this month. Some will be a missing file. Those
two look identical from here, which is exactly why they need naming rather than
guessing - and it is a list you can read in ten seconds after each morning's
sync.

(On 52600 specifically: its only line item is Website Visitor ID, which never
appears on a report, so even when it is loaded it correctly earns no row.)
