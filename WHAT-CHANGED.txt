1. DRIVE LINKS ARE FOLDERS, NOT ZIPS
-------------------------------------
Always have been. The link is
drive.google.com/drive/folders/<id> - the partner opens it and sees the client
names, takes the one they want, or copies the whole thing into their own drive.

A zip only appears when NEITHER Drive nor Dropbox is configured, as a last
resort so a delivery is not lost. On the links page that shows as "Download
zip" instead of "Open", so you can always tell which one you got.


2. STROUDSBURG - IT USED YOURS BECAUSE THE NAME STILL MATCHED
--------------------------------------------------------------
Which is luck, not a guarantee. The market folder is found by matching the
partner's name against the folders under the parent, so your fixed folder was
found because it is still called what the roster calls it. Rename it, merge it,
or move it and the match either finds something else or makes a new folder.

So folders can now be pinned. On the links page, under each partner: "Drive
folders (n)". Paste the folder's address from your browser - the whole URL, the
id is pulled out of it - and that market files there, with no matching at all.
Blank goes back to matching by name.


3. PACKAGING MOVED TO THE LINKS PAGE
-------------------------------------
"Package again" is off the partner card. The card is where reports get judged;
handing links over is a different job, and re-packaging belongs beside the link
it replaces rather than three screens away. The card now links across.

Partners that are ready but never packaged are on the links page too, under
"Ready, not packaged", so "Package & share" is in the same place as everything
else about links.


4. A SECOND LINK, ON PURPOSE
-----------------------------
Next to "Package again" there is a tag box and "New link".

  Package again    same folder, same link, files replaced under it
  New link         a separate folder with its own link

The tag becomes the folder name - "2026-07 July - corrected" in Drive,
"7 Mountains July 2026 Reports - corrected" in Dropbox - so six months from now
it still says what it was for. The tagged links are listed under the partner's
own one, and the partner's own link is never touched by making one.

A tagged copy also does not count as "what this report was last filed as", so
it cannot confuse the duplicate cleanup in the real folder.


5. THE MEMORY RESTART
----------------------
Standard 2 GB is the right call - keep it, and do not drop the worker count,
which is where speed would go.

Two changes so 2 GB is comfortable rather than just bigger:

  The order import kept one four-part tuple per line-item flight while it read
  a couple of million rows. That is five objects where one will do, and it was
  the largest thing the import held. It is one string now.

  gunicorn recycles a worker every ~800 requests, staggered so the two never
  recycle together. A slow leak now never reaches the ceiling; one worker cold
  starts while the other keeps serving, so nothing gets slower.

If it happens again, it will be during an order sync, and the next thing to
change is to run the sync in its own process rather than inside a web worker.
