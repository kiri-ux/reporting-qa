1. Why the product error kept coming back after I "fixed" it
--------------------------------------------------------------
This is the important one, and it's worse than it looked.

The order export is not stored. Every line item is turned into a product name
on the way in and only the product is kept. So fixing the mapping code does
nothing for the orders already in the database - and the S3 sync skips any
file whose ETag has not changed, so the export is never read again to correct
them. The wrong answer stands until somebody happens to upload a new export.

That is why 52753 still said DOOH after the DOOH fix shipped. The code was
right; the data it was reading had been mapped by the old code.

Fixed by making the mapping part of what "unchanged" means. The sync now
records which version of the mapping read the export, and re-reads it when
that version moves - automatically, in the background, on the first deploy
after a mapping change. After a re-read, reports for any client whose product
set actually moved are queued for a re-check. Only those clients: restamping
everything would re-read every PDF in the cycle daily for the same answer.


2. SKyPAC, order 51251 - no Video anywhere
-------------------------------------------
Two live line items: "TikTok Display & Video Ads" and "YouTube+ Video Ads".
Neither is a Video product. The words "Video Ads" are in the FORMAT half of
both names, and the matcher was finding them there.

The rule now is that the product LEADS the name and everything after it is the
format it is sold in. No amount of matching inside the tail gets "TikTok
Display & Video Ads" right, because "video ads" really is in there.

Also on that order: "Social Mirror CTV Ads" was not being mapped at all, so it
dropped out of the expected list and the report's Social Mirror CTV pages came
out as a product nobody had bought. It is its own line item to order and its
own widget on the report, so it is now its own product on both sides.

SKyPAC's four live line items now come out as TikTok, YouTube, Social Mirror,
Social Mirror CTV - which is exactly what the report carries. No finding.

There is a test that walks a product name through six different format tails
("", " Ads", " Display Ads", " Display & Video Ads", ...) and expects the same
answer each time, because the IO tool grows new spellings faster than anybody
updates a dictionary.

4. The stray "k" on an unreviewed row
---------------------------------------
Paulina's row showed "k" under the reporter and "k" in the sign-off box, on a
report in the ERRORS state with all three buttons live.

What happened: k signed it off, a re-check found a failure that was not there
when she signed, and the sign-off was correctly pulled - but her name stayed
printed as though it still stood.

The name has to survive, because somebody has to be told whose sign-off went.
So it is now marked as pulled instead: the row shows a "sign-off pulled" tag
that says on hover who signed it and why it went, the name is gone from the
reviewer column and the input box, and the report page says the same thing in
a sentence. Signing off again clears it.
