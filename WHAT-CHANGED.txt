1. The Render email - the health check was failing because it was working
--------------------------------------------------------------------------
Two things I did to you, both mine.

Your /healthz output says awaiting_recheck: 838. That queue is what caused the
email, and I made it expensive:

  a) The logo fingerprint shells out to pdftoppm - about a fifth of a second of
     CPU - and I had it running on EVERY re-check. 838 of those, two workers
     deep, on a box that is also meant to answer a five-second probe. The file
     cannot change under a re-check (a replacement goes through its own path
     and re-fingerprints there), so an existing fingerprint is reused now and
     only a report that has never had one pays for it.

  b) /healthz itself ran a COUNT over the reports table on every ping. The
     platform hits it every few seconds. A count that is fine on an idle box is
     not fine while the sweeper has the disk busy, and the probe timed out.
     /healthz is now build info only - no database. The queue depth moved to
     /healthz/deep, which is worth having and is not worth having on a liveness
     probe.

Together those take the sweep back under the duty cycle it was designed for.

4. Narrowing the pull, with the 2,000-day limit
-------------------------------------------------
The section is now a table you can expand in place - no download unless you
want one. Per partner: from, to, days, PULLS NEEDED, live line items, and the
exact date windows.

  - "To" is today for everybody, because a campaign that launched this morning
    has to be in the file.
  - Anything longer than 2,000 days is cut into consecutive windows, oldest
    first, each the full 2,000 except the last. Cutting from the recent end
    instead leaves the odd remainder on the oldest window, which is the one
    nobody wants to run twice.
  - A summary line up top says how many partners need more than one pull. If
    that number is small - and it usually is - the rest are one pull each and a
    daily sync becomes cheap.
