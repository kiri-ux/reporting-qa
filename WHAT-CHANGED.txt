AND WHY NO TEST COULD HAVE CAUGHT IT
=======================================
Every test runs against a tree where all the files are present. A file missed
on the way up is not a state the test suite can be in.

So there is a check for it now, and it is the one the failure suggests: read
every `from .x import a, b` in the app and confirm x really has a and b. Most
of those imports are inside functions - deliberately, it keeps startup fast -
which is exactly why a missing file sits there looking fine until somebody
opens the page that touches it.

It runs at startup, logs what it finds, and puts this at the top of EVERY page:

  This deploy is incomplete. Some files on the server are from an older build
  than the rest, so parts of the tool will fail as they are opened. Copy the
  missing files up:

    not have it - delivery.py on this box is from an older build than main.py

Which names the file to go and copy. /healthz/deep carries the same list and
returns ok:false while it is not empty, so it can be checked without opening
anything.

Two tests hold it: one runs the check against the repo itself, and one takes a
function out of delivery.py, boots the app, and fails unless the banner names
it.
