ONE MISSING SPACE
==================
This is mine and it is as dumb as it looks.

I added this line to the stylesheet in build 82:

    @media (prefers-reduced-motion:reduce){#tip{transition:none}}

An open brace followed straight by a hash - `{` then `#` - is how a template
comment starts. So the engine read everything from there as a comment until it
found a closer, which it never did: it swallowed the rest of the stylesheet,
the tag that closes it, and every tag after that. The browser got a document
whose stylesheet never ended, so it rendered the whole page as CSS text and
showed one line of footer.

The fix is a space:

    @media (prefers-reduced-motion:reduce){ #tip{transition:none} }

CSS does not care. The template engine does.


AND WHY 599 TESTS DID NOT CATCH IT
====================================
Because every one of them checks a status code or looks for a substring, and a
page that returns 200 with a broken stylesheet does both perfectly well. The
substring was even THERE - it was just inside a comment.

So there are two new tests:

  Every page is rendered with real data and the document is checked for
  balance - style, head, body, html, main, table, form, select, textarea - and
  that it ends with the closing html tag. Anything that swallows a chunk of
  the page now fails a test rather than shipping.

  And the same bug at the source: no template may contain an unterminated
  brace-hash, or that CSS shape at all.
