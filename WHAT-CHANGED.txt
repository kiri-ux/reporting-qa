1. ONE REPORTS GRID
--------------------
Signed-off reports had their own collapsed section at the bottom, so a report
changed which table it was in the moment somebody signed it, and finding it
again meant knowing that.

It is a filter now. Signed off and clear are hidden by default, with a chip
saying how many - click it and they appear in the same grid, sorted last.
Click it again and they go.

Fifty a page, with a pager. The old table was capped at 150 of 763 with a
"load all" that put four seconds of browser time on the page.


2. ORDER IDS LINK TO THE ORDER
-------------------------------
Every order id on the board is now a link to
reporting.zone/client/iotool/dist/#/items/viewOrder/<id>, opening in a new tab.
Rows carrying several ids link each one separately.

The base address is a setting (IO_ORDER_URL) so it can be changed without a
deploy if that tool ever moves.


3. "PACKAGE AGAIN" IS "SYNC REPORTS", WITH A TIMESTAMP
--------------------------------------------------------
"Package again" sounded like it made a new link. It does not - the same folder
gets the current files under the link the partner already has, which is the
whole point. It says "Sync reports", and beside it "last synced Aug 26,
1:55 PM", because otherwise there is no way to tell a link made before this
morning's corrections from one made after.

It is off the partner cards entirely now. That card is where reports get
judged.


4. THE BROKEN PIPE
-------------------
"Filing to Drive failed: BrokenPipeError: [Errno 32] Broken pipe" and it worked
on the third press. Nothing was wrong with the report - the connection went
away mid-upload, which is precisely the thing the tool should handle rather
than hand back.

Each file now retries up to four times, with Google's own retry inside that,
and a fresh upload object each attempt because the old one cannot be reused
after a failure. A file that truly will not go up says which file and how many
attempts it took to be sure.

And the failure no longer lands on the partner card. You packaged from the
links page, so it belongs there - the card just says the last sync failed and
points at the links page.


5. WHAT STATE EACH UNPACKAGED PARTNER IS IN
---------------------------------------------
"Ready, not packaged" now shows the report count, where it delivers, and - if
there was a failed attempt - when it failed and why on hover. A partner sitting
in that list because a sync broke looked exactly like one nobody had got to
yet, and that difference was the whole question.


6. THE RENAMED-FILE NOTE
-------------------------
Moved down beside "Replace the file", where the other facts about the file are,
and drawn as a plain grey line rather than a bordered warning panel. It is
housekeeping - what the file was called when it arrived and what it is filed as
now - and it was reading as something waiting on you.
