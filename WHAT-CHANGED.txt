WHAT SYNC ACTUALLY DOES - YOUR QUESTION, ANSWERED AND THEN FIXED
==================================================================
It used to upload every report in the partner, every time. Same folder, same
link, files replaced by name. Correct, and several minutes of nine-megabyte
uploads to change nothing.

Now it sends only what has actually moved. A report is sent when either:

  the name it should be filed under is not the name it was filed under
  the PDF itself is not the file it was filed from

The second is new: each report records the size and modified time of the PDF at
the moment it went up, so replacing a file makes it eligible again while a
re-check that changed nothing does not.

  Will it replace a file that was updated?   Yes - same name, overwritten.
  Will it remove the old one after a rename? Yes. Each report knows what it
  was last filed as, and only that exact name is removed. On Drive it goes to
  the trash rather than being destroyed. Nothing else in the folder is touched.
  Sync with nothing to send?                 Says "already up to date" and
  hands back the same link. Not an error.


1. THE CARD STARTS THE SYNC
----------------------------
"needs a sync" is a button now. It starts the sync, takes you to the links
page, scrolls to that partner and highlights the row - which stays marked while
it runs. Sending you there to find the row and press a second button was asking
you to do the work twice.


2. NO PACING ON A CAMPAIGN SOMEBODY CALLED OFF
------------------------------------------------
Sorge Funeral Home read "Meta is 100% short - 503 served against 400,000
ordered (20 months at the monthly figure on the order)" and "Campaign finished
100% under its goal". Twenty months it was never going to run.

Cancelling changes the deal. What a campaign was SOLD to deliver stopped being
what it was asked to deliver on the day somebody stopped it. Cancelled and
completed buys are no longer paced, on the monthly or the lifetime.


3. THE FALSE DATE ERROR ON THE SAME REPORT
--------------------------------------------
"Expected May 01, 2025 to Dec 31, 2026" on a campaign that finished in July.
Nothing ended inside the cycle window, so the check fell back to the latest end
date on the order - which is what it was sold to run to, eighteen months out.

When every line on a campaign is cancelled or complete, the expected end is now
where it actually stopped delivering, and the serving file supplies the day.


4. 49421 - COMPLETE, BUT STILL RUNNING INTO AUGUST
----------------------------------------------------
It ends 6 August, a day past this cycle's lifetime cutoff, and it delivered
every day of July. So it is still running, and its lifetime belongs to August.

45911 also reads complete, is dated to the end of December, and last delivered
mid-July - that one really has finished, and waiting for December means waiting
forever.

Nothing on the order separates those two. The last day with delivery on it
does: before month end means it stopped, at month end means it is still going.


5. 54169 - AND HOW TO SEE WHY ANY LIFETIME IS THERE
-----------------------------------------------------
The rules above may well have taken it off. If it is still there, the row now
says which of the two paths asked for it - hover the lifetime pill:

  "Order 54169 ends 2026-08-31"                       the date rule
  "Order 54169 is dated to 2026-12-31, but every line
   on this campaign is cancelled or complete, and it
   last delivered 2026-07-14"                         the finished rule

If it says the second and the order is live, that is a wrong cancelled/complete
flag on a line and I want the order id. If it says the first, the end date on
the order is inside this cycle.
