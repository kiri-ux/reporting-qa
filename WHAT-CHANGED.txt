AND ONE THING THAT MIGHT BE THE CAUSE
========================================
Build 113 put the flag catalogue in app/checks/. The rules fingerprint is a
hash of every file in that folder, and a changed hash queues EVERY report on
the board to be judged again - so deploying 113 started a re-check of the whole
cycle, on a file that contains no rules at all. Seven hundred reports, two
workers, each one re-reading a PDF.

That is bad on its own and I would move it regardless. It may also be what you
are looking at: a box busy enough re-reading seven hundred PDFs is a box that
can fail to draw a page.

The catalogue is now app/flag_catalog.py, outside that folder. DELETE
app/checks/catalog.py when you deploy this - if both exist the fingerprint
keeps the old value and the sweep starts again.

There is one more sweep either way, because removing the file changes the hash
back. It is the last one: after this, a wording fix in the catalogue costs
nothing.
