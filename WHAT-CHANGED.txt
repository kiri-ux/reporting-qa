A running sync now says what started it
-----------------------------------------
Short answer to your question: yes, it is normal, and yes, pressing the orders
button is one of the things that does it - but not the only one. THREE
different things can start a sync and none of them said so, which is why
opening the page and finding one running looked like the tool deciding to do
something on its own.

  1. You pressed the button - the one in the top right of the board, or Sync
     from S3 now on this page.
  2. The import rules changed on this deploy. The export is parsed once and
     only the answer is kept, so when the code that interprets it changes, the
     loaded orders are answering from an older version of it and the file has
     to be read again. This fires once per deploy that touches that code -
     which, while I have been shipping several builds a day, has been most of
     them.
  3. A batch of reports arrived. The order list is refreshed before
     completeness runs, so a campaign added or ended since the last run is
     already reflected. Reports have been arriving all day.

The page now says which:

    Sync running since 5:52 PM, because the import rules changed on this
    deploy, so the loaded orders were answering from an older version of them.

And the finished line says it too - "Last synced 6:04 PM (you pressed the
button) · 2,081 lines".

Nothing about the behaviour changed. It was always doing this; it just never
told you, and "is that normal?" is a question the page should have been able to
answer on its own.

Two things worth knowing while you are looking at it:

  - A sync that has been running more than 30 minutes is treated as dead - a
    deploy or restart mid-import - and stops blocking the next one. So a stuck
    claim cannot wedge it permanently.
  - Reason 2 stops happening once it has run successfully after a deploy. If
    you see it every time you open the page, that is reason 3, and it will
    settle when the reports stop arriving.
