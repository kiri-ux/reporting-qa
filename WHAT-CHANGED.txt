1. 51217 - AN RFP THE IMPORT COULD NOT SEE
--------------------------------------------
RFP was only ever read off the two STATUS columns. 51217 sits at Order Type
"Request for Proposal" with Order Status "Cancelled", so nothing said RFP
anywhere the import was looking, and a proposal that was never sold went on the
board owed a lifetime.

The TYPE column is where that fact actually lives. It is read now, and any
order whose type is a request for proposal is dropped the same way an RFP
status always was.

The orders re-read themselves on this deploy - the import fingerprint changed.


2. 50760 - SOLD, CANCELLED, NEVER SERVED
------------------------------------------
This one is a real insertion order, so the type does not catch it. Its own
notes say "Cancelled after pending launch for 2 months. No impressions served."

It was on the board because its end date falls inside this cycle, and a date is
all the order export has to offer. There is no report to pull for a campaign
with no delivery behind it, so a lifetime now needs the serving file to show
the client delivering in the data month.

This also replaces the narrower rule from build 75, which only applied the test
to campaigns closed out by the cancelled/complete flag. It applies to every
lifetime now. With no serving file loaded for a month, the dates stand on their
own exactly as before.


3. WHEN A CANCELLED CAMPAIGN ACTUALLY STOPPED
-----------------------------------------------
The end date on a cancelled order is what it was SOLD to run to. Nothing on the
export says when somebody hit cancel, so a lifetime pulled to that date covers
weeks of nothing.

A cancelled or completed campaign whose last delivery came before its end date
now carries "stopped 2026-07-12" on the board, with the full explanation on
hover. Pull the report to that date instead. A campaign that ran to its end
date is not annotated - saying so would put a note on half the board.


4. "NEEDS A SYNC" ON THE PARTNER CARD
---------------------------------------
Reports get corrected all cycle and the folder only changes when somebody
presses sync, so a partner could be handing out a perfectly good link to last
Tuesday's work with nothing saying so.

Each report records what it was last filed as, which makes this exact rather
than a guess: a name that does not match what it would be filed as now, or one
never filed at all, is a report the partner does not have. The card links
straight to the links page.


5. SIGN-OFF IS FILLED ICONS
-----------------------------
Reviewed, Needs fix and Waive are icons too now, filled rather than outlined -
on a row already carrying a partner, a client, five product chips, a date range
and a findings list, a pale outline reads as decoration.

The note box was being squeezed out of existence by the row's no-wrap layout.
It is back, and it widens when you click into it.


6. TOOLTIPS THAT ARRIVE WHEN YOU POINT AT THEM
------------------------------------------------
The browser's own title= tooltip takes about a second and a half to appear and
is drawn by the operating system, so it is both slow and the only thing on the
page that does not look like the page. They are the page's own now: instant,
dark, and readable, with the ones near the right edge flipped so they do not
run off it.
